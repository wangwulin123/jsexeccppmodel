# 构建与调试

## 1. 环境

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 x64 |
| 编译器 | MSVC（VS 2022 或 VS 2026），C++20 |
| CMake | ≥ 3.21 |
| CEF | 二进制发行包，需包含 `include/cef_app.h`、`cmake/`、`libcef.dll` |
| Qt | 6.x msvc 构建（Core / Widgets），示例使用 6.8.3 msvc2022_64 |

CEF 与 Qt **不在仓库内**。顶层 `CMakeLists.txt` 的默认探测路径：

```cmake
CEF_ROOT = <repo>/../../cef_binary
CMAKE_PREFIX_PATH = <repo>/../../qt/6.8.3/msvc2022_64
```

路径不匹配时必须显式传入，否则只会构建不依赖 CEF/Qt 的核心层。

## 2. 配置与构建

```powershell
$root = "C:\Users\me\jsapi_demo"

cmake -S $root -B "$root\build" -G "Visual Studio 18 2026" -A x64 `
      -DCEF_ROOT="C:\deps\cef_binary" `
      -DCMAKE_PREFIX_PATH="C:\deps\qt\6.8.3\msvc2022_64"

cmake --build "$root\build" --config Release --target `
      jsapi_qt_host demo_plugin jsapi_self_test -- /m
```

只构建核心层（无 CEF/Qt 也能跑）：

```powershell
cmake --build "$root\build" --config Release --target jsapi_self_test -- /m
& "$root\build\bin\Release\jsapi_self_test.exe"
```

关闭宿主目标：

```powershell
cmake -S $root -B "$root\build" -DJSAPI_BUILD_QT_HOST=OFF
```

### 构建目标

| 目标 | 类型 | 依赖 | 说明 |
| --- | --- | --- | --- |
| `jsapi_core` | 静态库 | 无 | `JsValue` / 函数表 / 节点基类 / 注册表 |
| `jsapi_rpc` | 静态库 | `jsapi_core` | 请求解析与分发 |
| `jsapi_bridge` | 静态库 | CEF + 上述两者 | 渲染进程/浏览器进程桥 |
| `jsapi_host_nodes` | 静态库 | `jsapi_core` | 静态注册节点示例 |
| `demo_plugin` | 动态库 | `jsapi_core` + Qt Widgets | 插件示例 |
| `jsapi_self_test` | 可执行 | `jsapi_rpc` + `jsapi_host_nodes` | 113 条自测 |
| `jsapi_qt_host` | 可执行 | CEF + Qt + bridge | Qt 宿主 |

### 产物位置

```
build/
├─ apps/qt_host/Release/
│  ├─ jsapi_qt_host.exe
│  ├─ demo_plugin.dll
│  ├─ jsapi_demo.html
│  ├─ jsapi_perf.html
│  ├─ libcef.dll / chrome_elf.dll / *.pak / locales / ...
│  └─ Qt6Core.dll / Qt6Gui.dll / Qt6Widgets.dll / platforms/qwindows.dll
└─ bin/Release/
   ├─ jsapi_self_test.exe
   └─ demo_plugin.dll
```

POST_BUILD 会自动完成插件、示例页、Qt DLL 与平台插件的拷贝，把 `apps/qt_host/Release` 整个目录拷走即可运行。

## 3. 运行

```powershell
# 默认加载 exe 同目录的 jsapi_demo.html
.\build\apps\qt_host\Release\jsapi_qt_host.exe

# 指定页面
.\build\apps\qt_host\Release\jsapi_qt_host.exe --url=file:///C:/work/jsapi_perf.html
```

| 参数 | 说明 |
| --- | --- |
| `--url=<url>` | 覆盖启动页面，支持 `file:///` 与 `http(s)://` |

运行时会生成 `cef_cache`（`root_cache_path`），可随时删除。

### 页面说明

| 页面 | 用途 |
| --- | --- |
| `jsapi_demo.html` | 交互式功能示例：根节点、属性、同步/异步、Qt 集成、对象句柄、静态节点、事件、原生 UI、临时对象、错误处理 |
| `jsapi_perf.html` | 自动性能基准，结果以 `JSAPIBENCH {...}` 打到宿主 stderr |

## 4. 调试

### 4.1 自测

`jsapi_self_test` 不依赖 CEF/Qt，覆盖函数表查找、参数校验、同步/异步 RPC、属性读写、事件派发、临时对象引用计数、DLL 加载等。输出失败项与统计：

```powershell
& .\build\bin\Release\jsapi_self_test.exe
```

### 4.2 运行时观察

- **stderr**：bridge 的协议错误（`jsapi: bad sync request`、`jsapi: describe handle N failed`）都写 stderr。用 PowerShell 重定向可落盘：

  ```powershell
  .\jsapi_qt_host.exe 2> host_err.txt
  ```

- **`Extention.objectStats()`**：观察句柄槽位、存活临时对象、代理引用计数，验证是否有泄漏。
- **`demo.uiInfo()`**：返回 `on_gui_thread`、`call_thread`、`window_title`，确认执行点是否落在 GUI 线程。
- **Chrome DevTools**：CEF 默认未开启远程调试端口。需要时在 `main.cpp` 的 `CefSettings` 里加：

  ```cpp
  settings.remote_debugging_port = 9222;
  ```

  然后浏览器访问 `http://localhost:9222` 附加到渲染进程。

### 4.3 断点位置

| 想观察 | 位置 |
| --- | --- |
| JS 调用进入 | `JsApiFunctionHandler::Execute`（`src/bridge/jsapi_render_handler.cpp`） |
| 请求到浏览器 | `JsApiBrowserBridge::HandleSyncPayload` / `HandleAsyncRequest` |
| 插件执行 | `RpcHost::Process` → `member->function(...)` |
| 事件派发 | `JsObjectBase::EmitTo` → `JsApiBrowserBridge::OnEvent` |
| 对象释放 | `JsRegistry::ReleaseObject` |
| 句柄表 | `JsRegistry::Describe` |

## 5. 常见问题

### 找不到 CEF

```
CMake Warning: CEF_ROOT not found (...), jsapi_bridge / qt host skipped
```

传入正确的 `-DCEF_ROOT=<cef_binary 根目录>`（该目录下应有 `include/cef_app.h`）。

### 找不到 Qt

```
Qt Widgets / CEF not found, skip jsapi_qt_host target
```

传入 `-DCMAKE_PREFIX_PATH=<qt>/6.8.3/msvc2022_64`。注意必须是 **msvc** 构建的 Qt，且位数与生成器一致（x64）。

### 启动时报缺少 Qt6Core.dll / 找不到 windows 平台插件

`platforms/qwindows.dll` 与 Qt DLL 必须和 exe 同目录。确认 POST_BUILD 步骤执行成功；也可以手动：

```powershell
windeployqt --no-translations build\apps\qt_host\Release\jsapi_qt_host.exe
```

### `window.Extention` 不存在

通常是一次 describe 失败，页面控制台与宿主 stderr 会有 `jsapi: root describe failed`。检查：

1. `CefApp::GetRenderProcessHandler()` 是否返回了 `JsApiRenderHandler`；
2. 浏览器进程是否已创建 `JsApiBrowserBridge`（它负责创建同步通道并启动 worker）；
3. 同步通道初始化是否失败（stderr 有 `sync request channel init failed`）。

### 新注册的节点页面看不到

根节点属性在首次 describe 时固化，页面加载后新增节点需要**刷新页面**。所有 `RegisterNode` 应在创建浏览器之前完成。

### `demo_plugin.dll` 加载失败

`qWarning() << "load demo_plugin.dll failed"` 会打印 `LoadLibrary` 错误码：

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `126` (0x7E) | 找不到模块 | 插件依赖的 Qt DLL 不在搜索路径 |
| `193` (0xC1) | 不是有效的 Win32 程序 | 位数不匹配（x86 插件 x64 宿主） |
| `127` (0x7F) | 找不到导出 | 没有 `JSAPI_EXPORT_EXTENSION` |

### 同步调用卡住或超时

- 设置了 `SetMainThreadDispatcher` 但投递不是阻塞式：bridge 会在 task 完成前写回包，导致回包内容不完整或提前 `SetEvent`。必须用 `Qt::BlockingQueuedConnection` 或等价语义。
- 插件函数里阻塞等待渲染进程（例如 `QDialog::exec()`）：整条 RPC 链被占住，渲染侧 10 s 后抛 `sync jsapi call timed out`。改用非模态 `open()` 或异步接口。
- 浏览器侧 frame 已销毁：同步请求仍会尝试执行，但渲染侧因等待超时报错。

### 中文乱码

源文件需 UTF-8。所有目标已加 `/utf-8`；新增目标请复用 `jsapi_setup_target()`。

### 运行库不匹配（LNK2038 / 堆损坏）

CEF wrapper 默认 `/MT`，Qt 使用 `/MD`。顶层已设置：

```cmake
set(CEF_RUNTIME_LIBRARY_FLAG "" CACHE STRING "MSVC runtime flag used by CEF wrapper")
```

新增宿主时不要覆盖它。

### 性能数字看起来只有 0 / 0.1 / 0.2 ms

渲染进程的 `performance.now()` 被 Chromium 量化为 100 µs 步长，单次计时无法分辨 30 µs 级同步调用。测桥接耗时请用批量均值（见 [性能基准](性能基准.md)）。

## 6. 清理重建

```powershell
Remove-Item -Recurse -Force "$root\build"
cmake -S $root -B "$root\build" -G "Visual Studio 18 2026" -A x64 `
      -DCEF_ROOT="..." -DCMAKE_PREFIX_PATH="..."
```

`build/`、`out/`、`.vs/` 已在 `.gitignore` 中排除，不要把生成物提交进仓库。
