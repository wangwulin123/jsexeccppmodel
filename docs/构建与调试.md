# 构建与调试

## 1. 环境

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 x64 |
| 编译器 | MSVC（VS 2022 或 VS 2026），C++20 |
| CMake | ≥ 3.21 |
| CEF | 二进制发行包，需包含 `include/cef_app.h`、`cmake/`、`libcef.dll` |
| Qt | 6.x msvc 构建（Core / Widgets），示例使用 6.8.3 msvc2022_64 |

CEF 与 Qt **不在仓库内**。顶层 `CMakeLists.txt` 的默认探测路径：

```cmake
CEF_ROOT = <repo>/../../cef_binary
CMAKE_PREFIX_PATH = <repo>/../../qt/6.8.3/msvc2022_64
```

路径不匹配时必须显式传入，否则只会构建不依赖 CEF/Qt 的核心层。

## 2. 配置与构建

```powershell
$root = "C:\Users\me\jsapi_demo"

cmake -S $root -B "$root\build" -G "Visual Studio 18 2026" -A x64 `
      -DCEF_ROOT="C:\deps\cef_binary" `
      -DCMAKE_PREFIX_PATH="C:\deps\qt\6.8.3\msvc2022_64"

cmake --build "$root\build" --config Release --target `
      demo_app jsapi_self_test -- /m
```

只构建核心层（无 CEF/Qt 也能跑）：

```powershell
cmake --build "$root\build" --config Release --target jsapi_self_test -- /m
& "$root\build\bin\Release\jsapi_self_test.exe"
```

关闭宿主目标：

```powershell
# CEF_ROOT / Qt 缺失时会自动跳过 jsapi_cef / jsapi_qt / demo_app，
# 只构建 jsapi.dll + 自测；无需额外开关。
cmake -S $root -B "$root\build" -DCEF_ROOT=""
```

### 构建目标

| 目标 | 类型 | 依赖 | 说明 |
| --- | --- | --- | --- |
| `jsapi` | **动态库** | 无 | `JsValue` / 函数表 / 节点基类 / 注册表 / 同步通道（零 CEF、零 Qt） |
| `jsapi_host_nodes` | 静态库 | `jsapi` | 静态注册节点示例 |
| `jsapi_testing` | 接口库 | `jsapi` + `jsapi_host_nodes` | 自测的公共头入口，避免直连 `src/` |
| `demo_plugin` | 动态库 | `jsapi` + Qt Widgets | 插件示例（产物即客户端插件） |
| `jsapi_self_test` | 可执行 | `jsapi_testing` | 318 条自测（可靠性 / 系统 / 性能三层） |
| `jsapi_cef` | **动态库** | `jsapi` + CEF | 唯一依赖 CEF 的层；公共头 `jsapi_cef/runtime.h` 不含 CEF 类型 |
| `jsapi_qt` | **动态库** | `jsapi_cef` + Qt Widgets | Qt 容器层：`jsapi::qt::Runtime` + `WebContainer` |
| `demo_app` | 可执行 | `jsapi_qt` + `jsapi_host_nodes`（传递带出 `jsapi` / Qt） | 业务层示例（零 CEF include） |

### 产物位置

```
build/
├─ bin/Release/
│  ├─ demo_app.exe
│  ├─ jsapi.dll / jsapi_cef.dll / jsapi_qt.dll
│  ├─ demo_plugin.dll
│  ├─ jsapi_self_test.exe
│  ├─ jsapi_demo.html / jsapi_perf.html
│  ├─ libcef.dll / chrome_elf.dll / *.pak / locales / ...
│  └─ Qt6Core.dll / Qt6Gui.dll / Qt6Widgets.dll / platforms/qwindows(d).dll
└─ sdk/                          （cmake --install 后的 SDK 目录）
```

POST_BUILD 会自动完成插件、示例页、Qt DLL 与平台插件的拷贝，把 `bin\Release` 整个目录拷走即可运行。
Debug 配置使用 `platforms/qwindowsd.dll`，Release 使用 `platforms/qwindows.dll`，两者由 CMake 按配置自动选择。

### SDK 安装与头文件

```powershell
cmake --install build --config Release --prefix build/sdk
```

```
build/sdk/
├─ include/jsapi/          业务层唯一依赖
├─ include/jsapi_rpc/
├─ include/jsapi_channel/
├─ include/jsapi_cef/      CEF-free 的适配层公共头
├─ include/jsapi_qt/       容器层公共头
├─ include/host_nodes/     静态节点示例
├─ bin/jsapi.dll
├─ bin/jsapi_cef.dll
├─ bin/jsapi_qt.dll
└─ lib/cmake/jsapi/        find_package(jsapi)
```

`jsapi_cef` / `jsapi_qt` 依赖第三方（CEF / Qt），因此不作为可移植 CMake 包导出，只安装二进制与导入库；`jsapi` 与 `jsapi_host_nodes` 参与 `EXPORT`，消费方可以直接：

```cmake
find_package(jsapi REQUIRED)
target_link_libraries(my_app PRIVATE jsapi::jsapi)
```

### 运行期依赖

| 产物 | 必需依赖 |
| --- | --- |
| `jsapi.dll` | 无 |
| `jsapi_cef.dll` | `jsapi.dll`、`libcef.dll` 及 CEF 资源 |
| `jsapi_qt.dll` | `jsapi_cef.dll`、`jsapi.dll`、Qt6 Core/Gui/Widgets |

业务 exe 只链接自己需要的层：

- Qt 宿主：`jsapi_qt` + `jsapi`
- 非 Qt 宿主：`jsapi_cef` + `jsapi`
- 纯插件/工具进程：`jsapi`

运行期依赖由 PE 导入表链式拉起（`demo_app.exe` → `jsapi_qt.dll` → `jsapi_cef.dll` → `libcef.dll`），因此 `libcef.dll` 与 CEF 资源必须和 exe 同目录（POST_BUILD 已自动复制）。

### ABI 版本

`include/jsapi/jsapi_version.h` 里的 `JSAPI_ABI_VERSION` 是头文件与动态库的契约版本。

- 头文件与 DLL 必须来自同一次构建；
- 插件与宿主各自编译时应打印该值对账；
- 变更 ABI（增删虚函数、改类成员布局、改导出宏语义）必须递增该版本。

当前导出策略：`jsapi.dll` 用 `WINDOWS_EXPORT_ALL_SYMBOLS` 导出全部符号，`jsapi_cef` / `jsapi_qt` 用显式 `JSAPI_CEF_API` / `JSAPI_QT_API` 宏。**契约只包含公共头里声明的符号**，其余导出仅供框架内部使用。

### 分层边界强制

`CMakeLists.txt` 提供两个辅助函数，所有业务 target 都会经过它们：

```cmake
jsapi_setup_target(demo_app)      # 统一 /utf-8、C++20、WIN32 宏
jsapi_assert_no_cef(demo_app)     # 源码里出现 include/cef_ 即配置失败
```

`jsapi_assert_no_cef` 作用于 `demo_plugin`、`jsapi_host_nodes`、`jsapi_self_test`、`demo_app`。触发时报错示例：

```
[分层边界] target 'demo_plugin' 的业务源文件 demo/demo_plugin/demo_plugin.cpp
直接 include 了 CEF 头文件。
业务层只能使用 jsapi/ 与 jsapi_qt/ 的公共头；CEF 适配请留在 jsapi_cef 层。
```

此外，业务 target 的 `target_link_libraries` 里不出现 `libcef_lib` / `libcef_dll_wrapper`，CEF 的 include 路径也只对 `jsapi_cef` 可见（`PRIVATE`），从构建图上也切断了越界可能。分层职责与 include 矩阵见 [接入指南](接入指南.md) §1。

## 3. 运行

```powershell
# 默认加载 exe 同目录的 jsapi_demo.html
.\build\bin\Release\demo_app.exe

# 指定页面
.\build\bin\Release\demo_app.exe --url=file:///C:/work/jsapi_perf.html

# 多容器（每容器独立浏览器 + 独立同步通道）
.\build\bin\Release\demo_app.exe --pages=3
```

| 参数 | 说明 |
| --- | --- |
| `--url=<url>` | 覆盖启动页面，支持 `file:///` 与 `http(s)://` |
| `--pages=N` | 多标签页布局（默认 1），每个标签独立浏览器与同步通道，用于并发/隔离验证；标签在首次显示时才创建浏览器 |

运行时会生成 `cef_cache`（`root_cache_path`），可随时删除。

### 页面说明

| 页面 | 用途 |
| --- | --- |
| `jsapi_demo.html` | 交互式功能示例：根节点、属性、同步/异步、Qt 集成、对象句柄、静态节点、事件、原生 UI、临时对象、错误处理 |
| `jsapi_perf.html` | 自动性能基准，结果以 `JSAPIBENCH {...}` 打到宿主 stderr |

## 4. 调试

### 4.1 自测

`jsapi_self_test` 不依赖 CEF/Qt，按职责分三层组织，共 318 条检查：

| 套件 | 目录 | 关注点 | 用例 / 检查 | 典型耗时 |
| --- | --- | --- | --- | --- |
| `reliability` | `test/reliability/` | 单点功能 + 边界/异常/并发：JSON 与值模型、RPC 解析与分发、事件同步与重入、通道容量与并发、生命周期、线程亲和、可靠性边界 | 28 / 269 | ~1.7 s |
| `system` | `test/system/` | 端到端链路：插件加载 → describe → 调用 → 事件回环 → 卸载；双插件共存、缺失导出、同名节点 | 4 / 37 | ~11 ms |
| `perf` | `test/perf/` | 吞吐与延迟基线：属性读、函数调用、JSON 编解码、通道往返、插件调用 | 3 / 12 | ~280 ms |

```powershell
& .\build\bin\Release\jsapi_self_test.exe                 # 全部
& .\build\bin\Release\jsapi_self_test.exe --suite=reliability
& .\build\bin\Release\jsapi_self_test.exe --suite=system
& .\build\bin\Release\jsapi_self_test.exe --suite=perf
& .\build\bin\Release\jsapi_self_test.exe --list          # 列出套件与用例数
```

失败时进程返回非 0。框架保留 `CheckKnownIssue` 用于登记"已确认但暂不修"的 `src/` 缺陷（打印 `[WARN]` 且不计失败，避免既有缺陷让基线长期红）；当前三个曾登记的问题已修复并转回 `Check`，基线无 WARN。

### 4.2 变更影响面与测试准入

每次改动按下表选最小必跑集，最终合入前跑 `--suite=all`：

| 改动位置 | 必跑套件 | 说明 |
| --- | --- | --- |
| `src/core/`、`include/jsapi/` | reliability + system + perf | 值模型/RPC/事件/注册表语义变化会影响所有上层 |
| `src/rpc/`、`src/channel/`、`include/jsapi_rpc/`、`include/jsapi_channel/` | reliability（含 channel 用例）+ perf | 协议与传输改动必须回归超时、容量、并发 |
| `src/cef/`、`include/jsapi_cef/` | system + 手工浏览器回归 | 自测不含 CEF；必须跑 `demo_app` 检查页面加载与 `Extention` 可用 |
| `src/qt/`、`include/jsapi_qt/` | 手工浏览器回归 | 重点验证 `WebContainer` 首次显示尺寸、切 tab、缩放/多显示器 |
| `demo/`（插件、示例页） | system + 页面手测 | 插件 ABI/导出表变化会让 system 套件直接失败 |
| 仅文档 | 无 | — |

### 4.3 运行时观察

- **stderr**：bridge 的协议错误（`jsapi: bad sync request`、`jsapi: describe handle N failed`）都写 stderr。用 PowerShell 重定向可落盘：

  ```powershell
  .\demo_app.exe 2> host_err.txt
  ```

- **`Extention.objectStats()`**：观察句柄槽位、存活临时对象、代理引用计数，验证是否有泄漏。
- **`demo.uiInfo()`**：返回 `on_gui_thread`、`call_thread`、`window_title`，确认执行点是否落在 GUI 线程。
- **Chrome DevTools**：CEF 默认未开启远程调试端口。需要时在 `main.cpp` 的 `CefSettings` 里加：

  ```cpp
  settings.remote_debugging_port = 9222;
  ```

  然后浏览器访问 `http://localhost:9222` 附加到渲染进程。

### 4.3 断点位置

| 想观察 | 位置 |
| --- | --- |
| JS 调用进入 | `JsApiFunctionHandler::Execute`（`src/bridge/jsapi_v8_proxy.cpp`） |
| 请求到浏览器 | `JsApiBrowserBridge::OnRequestReady` → `RunTopLevel` |
| 同步请求解析与执行 | `JsApiBrowserBridge::ProcessPayload` → `RpcHost::Process` → `member->function(...)` |
| 嵌套请求内联执行 | `SyncChannel::DrainHandoffInline` / `JsApiBrowserBridge::DrainNestedQueue` |
| 事件派发（异步） | `JsObjectBase::EmitTo` → `JsApiBrowserBridge::OnEvent` |
| 事件派发（同步等待） | `JsObjectBase::DispatchEventSync` → `JsApiBrowserBridge::OnEventSync` |
| 渲染进程崩溃清理 | `JsApiBrowserBridge::OnRenderProcessTerminated` |
| 对象释放 | `JsRegistry::ReleaseObject` |
| 句柄表 | `JsRegistry::Describe` |

## 5. 常见问题

### 找不到 CEF

```
CMake Warning: CEF_ROOT not found (...), jsapi_bridge / qt host skipped
```

传入正确的 `-DCEF_ROOT=<cef_binary 根目录>`（该目录下应有 `include/cef_app.h`）。

### 找不到 Qt

```
Qt Widgets / CEF not found, skip jsapi_cef / jsapi_qt / demo_app targets
```

传入 `-DCMAKE_PREFIX_PATH=<qt>/6.8.3/msvc2022_64`。注意必须是 **msvc** 构建的 Qt，且位数与生成器一致（x64）。

### 启动时报缺少 Qt6Core.dll / 找不到 windows 平台插件

`platforms/qwindows.dll` 与 Qt DLL 必须和 exe 同目录。确认 POST_BUILD 步骤执行成功；也可以手动：

```powershell
windeployqt --no-translations build\bin\Release\demo_app.exe
```

### `window.Extention` 不存在

通常是一次 describe 失败，页面控制台与宿主 stderr 会有 `jsapi: root describe failed`。检查：

1. `CefApp::GetRenderProcessHandler()` 是否返回了 `JsApiRenderHandler`；
2. 浏览器进程是否已创建 `JsApiBrowserBridge`（它负责创建同步通道并启动 worker）；
3. 同步通道初始化是否失败（stderr 有 `sync request channel init failed`）。

### 新注册的节点页面看不到

根节点属性在首次 describe 时固化，页面加载后新增节点需要**刷新页面**。所有 `RegisterNode` 应在创建浏览器之前完成。

### `demo_plugin.dll` 加载失败

`qWarning() << "load demo_plugin.dll failed"` 会打印 `LoadLibrary` 错误码：

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `126` (0x7E) | 找不到模块 | 插件依赖的 Qt DLL 不在搜索路径 |
| `193` (0xC1) | 不是有效的 Win32 程序 | 位数不匹配（x86 插件 x64 宿主） |
| `127` (0x7F) | 找不到导出 | 没有 `JSAPI_EXPORT_EXTENSION` |

### 同步调用卡住或超时

- 设置了 `SetMainThreadDispatcher` 但投递不是阻塞式：bridge 会在 task 完成前写回包，导致回包内容不完整或提前 `SetEvent`。必须用 `Qt::BlockingQueuedConnection` 或等价语义。
- 插件函数里阻塞等待渲染进程（例如 `QDialog::exec()`）：整条 RPC 链被占住，渲染侧 10 s 后抛 `sync jsapi call timed out`。改用非模态 `open()` 或异步接口。超时只放弃等待，**已开始的插件函数仍会继续执行**，需要保证函数幂等。
- 浏览器侧 frame 已销毁 / 渲染进程崩溃：同步事件立刻返回 `render process terminated`，不会等满 10 s；页面重载后的首次同步调用会重建通道。

### 页面刷新后，原来注册的事件回调不再触发

预期行为：旧 document 的 V8 上下文已销毁，框架会在新 document 建根对象时清理该浏览器的旧监听器。页面加载后需重新 `addEventListener`。

### 调用操作 Qt 控件的成员后进程崩溃

成员没有声明 `ThreadAffinity::UI`，实际在 Worker 线程操作了 GUI 对象。把该成员改为 UI 亲和（或改为把操作投递回宿主主线程）即可。

### 同步事件报 `event callback not found`

通常是监听器已失效（页面已刷新/渲染进程重启）。框架会清理旧监听器并让该事件立即失败；在新页面重新注册监听即可，不要缓存跨页面的 `callback` 句柄。

### 中文乱码

源文件需 UTF-8。所有目标已加 `/utf-8`；新增目标请复用 `jsapi_setup_target()`。

### 运行库不匹配（LNK2038 / 堆损坏）

CEF wrapper 默认 `/MT`，Qt 使用 `/MD`。顶层已设置：

```cmake
set(CEF_RUNTIME_LIBRARY_FLAG "" CACHE STRING "MSVC runtime flag used by CEF wrapper")
```

新增宿主时不要覆盖它。

### 性能数字看起来只有 0 / 0.1 / 0.2 ms

渲染进程的 `performance.now()` 被 Chromium 量化为 100 µs 步长，单次计时无法分辨 30 µs 级同步调用。测桥接耗时请用批量均值（见 [性能基准](性能基准.md)）。

## 6. 清理重建

```powershell
Remove-Item -Recurse -Force "$root\build"
cmake -S $root -B "$root\build" -G "Visual Studio 18 2026" -A x64 `
      -DCEF_ROOT="..." -DCMAKE_PREFIX_PATH="..."
```

`build/`、`out/`、`.vs/` 已在 `.gitignore` 中排除，不要把生成物提交进仓库。
