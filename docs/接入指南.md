# 接入指南

本文说明如何把 JSAPI Lite 接入一个 CEF 宿主，并为前端提供可调用的 C++ 能力。

接入只有三件事：

1. **声明节点**：写一个 `JsObjectBase` 子类，在 `DeclareMembers()` 里填函数表。
2. **注册节点**：动态库插件导出工厂，或静态注册到宿主。
3. **宿主装配**：渲染进程挂 `JsApiRenderHandler`，浏览器进程挂 `JsApiBrowserBridge` 并转发进程消息。

---

## 1. 分层与设计约定

### 1.1 依赖方向

```
┌───────────────────────────────────────────────────────────────┐
│ 业务层   demo/（demo_app · demo_plugin · host_nodes）           │
│ 允许 include：jsapi/*.h、jsapi_qt/*.h（非 Qt 宿主：jsapi_cef/*.h）│
└───────────────────────────┬───────────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────────┐
│ L3 容器层  jsapi_qt.dll                                        │
│   include/jsapi_qt/{runtime.h, web_container.h}                │
│   jsapi::qt::Runtime      —— 装配 Qt 线程投递器                │
│   jsapi::qt::WebContainer —— QWidget 容器（pimpl 包 CefClient） │
│ 依赖：Qt6::Widgets、jsapi_cef、jsapi                            │
└───────────────────────────┬───────────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────────┐
│ L2 适配层  jsapi_cef.dll                                       │
│   include/jsapi_cef/runtime.h —— 不含任何 CEF 类型              │
│   jsapi::cef::Runtime      —— 子进程分流 / CefInitialize /     │
│                               注册表 / 插件加载 / 投递器装配     │
│   jsapi::cef::BrowserHandle—— CEF-free 浏览器句柄               │
│   私有实现：BrowserBridge / RenderHandler / V8 代理 / CefApp    │
│ 依赖：libcef.dll、libcef_dll_wrapper、jsapi                     │
└───────────────────────────┬───────────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────────┐
│ L1 执行模型层  jsapi.dll                                       │
│   include/jsapi/         JsValue / 函数表 / JsObjectBase /      │
│                          JsRegistry / 插件加载 / ABI 版本       │
│   include/jsapi_rpc/     请求解析与按索引分发                   │
│   include/jsapi_channel/ 共享内存 + 命名事件通道、渲染侧同步通道 │
│ 依赖：无（仅 Win32 API）                                        │
└───────────────────────────────────────────────────────────────┘
```

箭头**只能向下**。反向依赖（L1 出现 CEF、L2 出现 Qt 控件、业务层出现 CEF）都是设计错误，构建期会拦截。

### 1.2 每一层的职责与产物

| 层 | DLL | 公共头 | 职责 | 允许依赖 | 不该出现的东西 |
| --- | --- | --- | --- | --- | --- |
| L1 执行模型层 | `jsapi.dll` | `include/jsapi/`、`jsapi_rpc/`、`jsapi_channel/` | `JsValue`、函数表、节点基类、句柄注册表、插件加载、同步 RPC 通道 | 仅 Win32 | CEF、Qt、窗口句柄 |
| L2 CEF 适配层 | `jsapi_cef.dll` | `include/jsapi_cef/` | 子进程分流、`CefInitialize`、浏览器句柄、V8 代理、进程消息 | CEF、L1 | Qt 控件、业务规则 |
| L3 Qt 容器层 | `jsapi_qt.dll` | `include/jsapi_qt/` | `jsapi::qt::Runtime`（Qt 线程投递器）+ `WebContainer`（QWidget 容器） | Qt、L2 | CEF 类型（公共头里）、业务规则 |
| 业务层 | `demo_app.exe`、`demo_plugin.dll`、`test/` | — | 只写业务：注册节点、开容器、摆窗口 | L1（Qt 宿主再加 L3） | CEF、`windows.h`（插件示例除外） |

三条落在目录上的硬规则：

- **`demo/` 只放业务示例代码。** 宿主职责（`CefApp`、`CefClient`、窗口包装、CEF 初始化）都在 L2/L3，`demo/demo_app/main.cpp` 只剩「加载插件 + 开容器 + 摆窗口」。
- **CEF 内部头一律留在 `src/cef/`。** `jsapi_browser_bridge.h`、`jsapi_render_handler.h`、`jsapi_render_core.h` 不在 `include/`，业务代码不可能误 include。
- **L2 的公共头没有 CEF 类型。** `jsapi_cef/runtime.h` 只出现 `std::string` / `std::function` / `void*`（HWND），因此非 Qt、非 CEF 的宿主可以直接接入并自备容器。

### 1.3 include 矩阵

| 使用者 | `jsapi/` | `jsapi_rpc/` | `jsapi_channel/` | `jsapi_cef/` | `jsapi_qt/` | `src/cef/*` |
| --- | :-: | :-: | :-: | :-: | :-: | :-: |
| 业务插件 `demo/demo_plugin` | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 业务 exe `demo/demo_app`（Qt） | ✅ | ✅ | ✅ | ⚠️ 仅 `runtime.h` | ✅ | ❌ |
| 测试 `test/*` | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 非 Qt 宿主 | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| 适配层 `src/cef` | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| 容器层 `src/qt` | ✅ | — | — | ✅ | ✅ | ❌ |

`jsapi_channel/` 属于「高级接口」：正常业务不需要直接使用，它是同步 RPC 的传输层，也是自测覆盖的对象。

### 1.4 业务开发者如何使用

按宿主形态选一条路径即可，**业务代码只需认识伞形入口**：

| 场景 | 链接目标 | 传递带出 | 公共头 |
| --- | --- | --- | --- |
| Qt 宿主（推荐） | `jsapi_qt`（+ 业务节点库） | `jsapi_cef`、`jsapi`、Qt6::Widgets | `jsapi_qt/`、`jsapi/` |
| 非 Qt 宿主（Win32/MFC/自绘） | `jsapi_cef` | `jsapi` | `jsapi_cef/`、`jsapi/` |
| 纯插件 / 工具进程 | `jsapi` | — | `jsapi/` |

```cmake
# Qt 宿主
target_link_libraries(my_host PRIVATE jsapi_qt)
# 非 Qt 宿主
target_link_libraries(my_host PRIVATE jsapi_cef)
# 业务插件
target_link_libraries(my_plugin PRIVATE jsapi)   # 需要操作控件时才加 Qt6::Widgets
```

传递链是这样工作的：

- **构建期**：`jsapi_qt` 以 `PUBLIC` 依赖 `jsapi_cef`，`jsapi_cef` 以 `PUBLIC` 依赖 `jsapi`，CEF 的导入库则是 `PRIVATE`。所以链接行只写 `jsapi_qt`，CMake 会自动补出 `jsapi_cef.lib`、`jsapi.lib`，而 `libcef.lib` 止步于 L2。
- **运行期**：`demo_app.exe` 的导入表只记录 `jsapi_qt.dll`；加载器读取 `jsapi_qt.dll` 自己的导入表拉出 `jsapi_cef.dll`，再拉出 `libcef.dll`。这条链由 PE 导入表决定，与 PUBLIC/PRIVATE 无关。
- **约束**：业务源码一旦 include 了 `include/cef_*`，CMake 配置期直接失败（`jsapi_assert_no_cef`），CEF 的 include 路径也只对 `jsapi_cef` 可见。

具体代码见 §4「宿主接入」、§3「注册节点」；各层二进制的交付与 ABI 契约见 [构建与调试](构建与调试.md)。

### 1.5 核心概念与进程边界

| 概念 | 说明 |
| --- | --- |
| 根节点 | `window.Extention`，固定句柄 `0`，由 `JsRegistry` 在构造时创建 |
| 命名节点 | 通过 `RegisterNode("demo", factory)` 注册，在根节点上表现为属性 `Extention.demo` |
| 句柄 | 每个 C++ 对象在浏览器进程有一个自增 `handle`；跨进程只传句柄数字 |
| 代理 | 渲染进程为每个句柄建立一个 V8 对象，方法调用/属性访问都转成 RPC |
| 函数索引 | 声明顺序即 `index`；请求只带 `(handle, index)`，不传函数名 |
| 生命周期 | `Singleton`（进程内复用）或 `Transient`（随 JS 代理回收释放） |

渲染进程与浏览器进程的职责边界：

- 渲染进程**不持有业务对象**，只持有 V8 代理、回调函数和待回包 Promise。
- 浏览器进程**不接触 V8**，只处理 `JsValue` 与 JSON。

## 2. 声明节点

### 2.1 最小节点

```cpp
// my_node.h
#pragma once

#include "jsapi/js_object.h"

class MyNode final : public jsapi::JsObjectBase {
 protected:
  void DeclareMembers(jsapi::JsTableBuilder& table) const override {
    // 函数：名字、返回类型、参数表、实现
    table.Function(
        "add", jsapi::JsType::Int,
        {{"a", jsapi::JsType::Int}, {"b", jsapi::JsType::Int}},
        [](jsapi::JsObjectBase* /*self*/, jsapi::JsCallContext& ctx) {
          ctx.Return(jsapi::JsValue::Int(ctx.args()[0].AsInt() +
                                         ctx.args()[1].AsInt()));
        });

    // 只读属性
    table.Property("version", jsapi::JsType::String,
                   [](jsapi::JsObjectBase*) {
                     return jsapi::JsValue::String("my-1.0.0");
                   });

    // 可写属性：setter 返回 false 表示失败，error 会变成 JS 异常
    table.Property(
        "limit", jsapi::JsType::Int,
        [](jsapi::JsObjectBase* self) {
          return jsapi::JsValue::Int(static_cast<MyNode*>(self)->limit_);
        },
        [](jsapi::JsObjectBase* self, const jsapi::JsValue& value,
           std::string* error) {
          const std::int64_t next = value.AsInt();
          if (next < 0) {
            if (error) *error = "limit must be >= 0";
            return false;
          }
          static_cast<MyNode*>(self)->limit_ = next;
          return true;
        });
  }

 private:
  std::int64_t limit_ = 10;
};
```

### 2.2 声明函数

```cpp
JsTableBuilder& Function(const std::string& name,
                         JsType return_type,
                         std::vector<Param> params,
                         JsFunction function,
                         bool async = false);

JsTableBuilder& AsyncFunction(const std::string& name,
                              JsType return_type,
                              std::vector<Param> params,
                              JsFunction function);
```

- `Param` 支持聚合初始化：`{"name", JsType::Int}`，第三个字段 `optional` 默认为 `false`。
- 参数个数会被严格校验：必须落在 `[必填数, 声明总数]` 区间，否则报错。
- 声明类型用于**入参强转**（见 [API 参考](API参考.md#参数与返回值校验)）；返回值类型只写入 describe 信息，不做运行时转换，插件应返回匹配的 `JsType`。
- `AsyncFunction` 等价于 `Function(..., async = true)`。

参数表只在**首次访问**时构建并缓存，因此 `DeclareMembers` 应该是纯声明，不要在里面对可变状态做判断。若声明依赖会变化的状态，调用 `InvalidateTable()` 使其重建。

### 2.3 返回与报错

```cpp
void Return(JsValue value);   // 正常返回
void Fail(std::string error); // 失败：渲染进程会收到 JS 异常（同步）或 Promise reject（异步）
```

同步调用中 `Fail()` 会以 `throw` 形式抛出；异步调用中会 `Promise.reject(error)`。

### 2.4 返回对象句柄

一个节点可以返回另一个 C++ 对象，渲染进程会为它单独 describe 并建立新的 V8 代理：

```cpp
table.Function("child", jsapi::JsType::ObjectHandle, {},
               [](jsapi::JsObjectBase* /*self*/, jsapi::JsCallContext& ctx) {
                 auto child = std::make_shared<MyChildNode>();
                 ctx.Return(jsapi::JsValue::ObjectHandle(
                     ctx.registry()->AddObject(child, ctx.env())));
               });
```

`ctx.registry()` 是浏览器进程的句柄注册表，`ctx.env()` 是本次调用所在的 `(browser, frame)`。**推荐把 `env` 带上**，事件才能按来源定向回送。

### 2.5 生命周期

```cpp
class MyChildNode final : public jsapi::JsObjectBase {
 public:
  JSAPI_NODE_LIFE_TYPE(jsapi::LifeType::Transient);  // 随代理回收释放
};
```

| 类型 | 行为 | 适用 |
| --- | --- | --- |
| `Singleton`（默认） | 命名节点首次访问时创建，句柄缓存，所有页面共用同一个实例 | 全局服务、配置、会话 |
| `Transient` | 每次 `AddObject` / 访问都新建，渲染进程代理被 GC 时按引用计数释放 | 每次调用产生的新对象、临时上下文 |

生命周期由类内宏写死，注册时不可覆盖。`Singleton` 的对象在宿主进程存活期内不会被释放。

### 2.6 事件

所有节点自动拥有四个事件函数，**不需要在 `DeclareMembers` 里重复声明**：

| JS 方法 | 说明 |
| --- | --- |
| `addEventListener(event, fn)` | 登记回调，绑定当前 `(browser, frame)`；非法回调（非函数）由协议层直接报错，C++ 侧 `AddEventListener` 返回 `false` 时页面同样收到 `false` |
| `removeEventListener(event, fn)` | 移除回调（同一 JS 函数对象复用同一回调句柄） |
| `dispatchEvent(event, args?, options?)` | 派发；`options` 支持 `{ browser, frame, excludeSelf }`。广播时各监听器互相隔离：单个监听抛异常不影响其余监听，也不会中断调用方 |
| `getAllEventInfo()` | 返回 `[{ event, callback, browser, frame }]` |

> 头文件 `addEventListener` 只有回调句柄合法且事件名非空才登记成功，否则返回 `false`，页面应据此判断是否登记成功（不要假定恒为 `true`）。

C++ 侧主动通知：

```cpp
// 广播给所有监听者
int count = self->BroadcastEvent("progress", {JsValue::Int(50)});

// 只发给指定页面
jsapi::RpcEnv target;
target.browser_id = 1;      // <0 表示不限
target.frame_id = "2";      // 空表示不限
self->DispatchEvent("progress", target, {JsValue::Int(50)});
```

JS 回调签名固定为 `(eventName, ...args)`：

```js
demo.addEventListener("progress", (name, value) => {
  console.log(name, value);  // "progress" 50
});
```

> 事件从插件执行线程（默认 Worker，`ThreadAffinity::UI` 的成员为宿主 UI 线程）出发，优先写入该浏览器的共享内存环形缓冲，槽位占满时经 `CefPostTask` 投递到 CEF UI 线程再 `SendProcessMessage` 到渲染进程，因此是**异步**的，不保证与调用同一时刻到达。

## 3. 注册节点

### 3.1 方式一：动态库插件

插件是一个导出 `GetExtensionJsApiObj()` 的 DLL：

```cpp
// my_plugin.cpp
#include "my_node.h"
#include "jsapi/js_registry.h"

JSAPI_EXPORT_EXTENSION(MyNode);   // 展开成 extern "C" __declspec(dllexport) 工厂
```

CMake：

```cmake
add_library(my_plugin SHARED my_node.cpp my_plugin.cpp)
target_link_libraries(my_plugin PRIVATE jsapi_core Qt6::Widgets)  # 需要 Qt 时才链接
set_target_properties(my_plugin PROPERTIES PREFIX "" OUTPUT_NAME "my_plugin")
```

宿主加载：

```cpp
std::string error;
auto factory = jsapi::plugins::LoadDll("C:\\path\\my_plugin.dll", &error);
if (factory) {
  bridge->registry().RegisterNode("my", std::move(factory));
} else {
  // error 含 LoadLibrary / GetProcAddress 失败原因
}
```

- DLL 会被**常驻加载**（不 `FreeLibrary`），避免对象析构时模块已卸载。
- 插件依赖的 Qt DLL 必须能被找到；示例工程在 POST_BUILD 阶段把 Qt DLL 拷到 exe 同目录。
- 工厂返回裸指针，由 `std::shared_ptr` 接管（`LoadDll` 内已包装）。

### 3.2 方式二：静态注册

直接编进宿主的节点，不需要 DLL 边界：

```cpp
std::shared_ptr<jsapi::JsObjectBase> CreateHostNode() {
  return std::make_shared<HostNode>();
}

bridge->registry().RegisterNode("host", &CreateHostNode);
```

也可以注册现成实例（首次访问时才挂到句柄表）：

```cpp
bridge->registry().RegisterNode("host", std::make_shared<HostNode>());
```

### 3.3 注册时机

根节点的属性来自注册的节点名，函数表在**首次 describe 时构建**：

- 同名节点重复注册会保留已实例化对象的句柄，页面上已有的代理继续指向原对象。
- 页面加载**之后**新增的节点，当前页面不会自动多出属性，需要刷新页面。
- 因此应在创建浏览器窗口之前完成所有 `RegisterNode`。

## 4. 宿主接入

宿主不再需要自己实现 `CefApp` / `CefClient` / 窗口包装——这些已经封装进 `jsapi_cef.dll` 与 `jsapi_qt.dll`。宿主只需选一条接入路径：

| 路径 | 依赖 | 适用 |
| --- | --- | --- |
| Qt 宿主 | `jsapi_qt` + `jsapi` | QWidget 应用（推荐） |
| 非 Qt 宿主 | `jsapi_cef` + `jsapi` | Win32 / MFC / 自绘 UI，自备容器 |

两条路径都必须遵守的进程模型约束见 §4.5，核心只有一条：`RunSubprocess()` 必须在 `main` 最开头、UI 初始化之前调用。

### 4.1 Qt 宿主

```cpp
#include <QApplication>
#include "jsapi_qt/runtime.h"
#include "jsapi_qt/web_container.h"

int main(int argc, char* argv[]) {
  if (int code = jsapi::qt::Runtime::RunSubprocess(); code >= 0) return code;

  QApplication app(argc, argv);
  jsapi::qt::Runtime runtime(&app);          // CefInitialize + Qt 线程投递器
  runtime.registry().RegisterNode("host", &CreateHostNode);
  runtime.LoadPlugin("my_plugin.dll", "demo");

  QMainWindow win;
  auto* web = new jsapi::qt::WebContainer(&runtime);
  web->LoadUrl(QUrl::fromLocalFile("index.html"));
  win.setCentralWidget(web);
  win.show();
  return app.exec();                          // ~Runtime → 关浏览器 → CefShutdown
}
```

`jsapi::qt::Runtime` 内部已经装好两个投递器，不需要再手工设置：

- `SetMainThreadDispatcher` → `QMetaObject::invokeMethod(..., Qt::BlockingQueuedConnection)`，供 `ThreadAffinity::UI` 成员使用；
- `SetMainThreadPoster` → `Qt::QueuedConnection`，作为 `DispatchEventSync` 的能力开关。

### 4.2 非 Qt 宿主

```cpp
#include "jsapi_cef/runtime.h"

if (int code = jsapi::cef::Runtime::RunSubprocess(); code >= 0) return code;

jsapi::cef::Runtime runtime;
runtime.SetMainThreadDispatcher(PostToUiThreadBlocking);  // 必须阻塞
runtime.SetMainThreadPoster(PostToUiThread);              // 非阻塞，可留空

jsapi::cef::BrowserOptions opt;
opt.parent_handle = my_hwnd;      // 你的原生子窗口
opt.width = 800; opt.height = 600;
opt.device_scale_factor = dpi_scale;
opt.url = "file:///.../index.html";
auto browser = runtime.CreateBrowser(opt);    // 之后用 Resize / LoadUrl / Close
```

`jsapi_cef/runtime.h` 不含任何 CEF 类型，因此非 Qt 宿主不需要 CEF 头文件与 CEF include 路径，也不需要实现 `CefApp`/`CefClient`。

### 4.3 执行线程

每个浏览器一条请求通道，配一条**读取线程**（`req_evt` 的唯一等待者，只收不发）和一条**会话线程**（执行该页面的函数体）：

| 场景 | 执行线程 |
| --- | --- |
| 同步 RPC（默认 `ThreadAffinity::Worker`） | 该页面的会话线程 |
| 同步 RPC（`ThreadAffinity::UI`） | 宿主 UI 主线程（经 dispatcher 阻塞切换） |
| 异步 RPC | 宿主 UI 主线程 |
| 同步事件里的嵌套请求 | 触发事件的那条会话线程（内联执行） |
| 释放临时对象 | 宿主 UI 主线程 |

约定：**dispatcher 必须在返回前执行完 task**（阻塞式）。示例使用 Qt 的 `Qt::BlockingQueuedConnection`，因为 bridge 在 dispatcher 返回后立刻使用函数体的结果。

函数级亲和由插件声明，默认 Worker：

```cpp
// 默认 Worker：不需要 UI 线程的操作（计算、IO、注册表等）都留在会话线程
table.Function("readFile", jsapi::JsType::String, {{"path", jsapi::JsType::String}},
               ReadFileImpl);

// 操作 Qt 控件：显式声明 UI 亲和
table.Function("setWindowTitle", jsapi::JsType::Bool,
               {{"title", jsapi::JsType::String}}, SetTitleImpl,
               /*async=*/false, jsapi::ThreadAffinity::UI);
```

插件函数按"每页面一条会话线程"执行：**同一页面内串行，不同页面之间并行**。因此跨页面共享的节点状态需要插件自己加锁；但**不要在插件函数里阻塞等待渲染进程**（例如模态 `QDialog::exec()`），否则会卡住该页面的 RPC 链。示例用非模态 `QMessageBox::open()`。

### 4.4 CMake 依赖

```cmake
# Qt 宿主（最常见）：只写伞形入口，jsapi_cef / jsapi / Qt6 由 PUBLIC 依赖传递带出
target_link_libraries(my_host PRIVATE
  jsapi_qt         # 容器层：Runtime + WebContainer
  jsapi_host_nodes # 静态节点（如需要）
)

# 非 Qt 宿主：jsapi 由 jsapi_cef 传递带出
target_link_libraries(my_host PRIVATE
  jsapi_cef
  jsapi_host_nodes
)

# 业务插件
target_link_libraries(my_plugin PRIVATE jsapi Qt6::Widgets)  # 需要操作控件时才链 Qt
```

`jsapi` 不依赖 CEF/Qt，可在没有 CEF 的环境里单独构建和单测；业务层 target 一旦 include 了 CEF 头，CMake 配置期会直接报错（`jsapi_assert_no_cef`）。各层职责与传递规则见 §1.4。

### 4.5 进程模型硬约束

以下约束由 CEF 进程模型决定，不是框架限制：

| 约束 | 原因 | 框架的处理 |
| --- | --- | --- |
| `RunSubprocess()` 必须在 `main` 最开头 | renderer/GPU 子进程复用同一个 exe | `jsapi::qt::Runtime::RunSubprocess()` / `jsapi::cef::Runtime::RunSubprocess()` 返回 `>= 0` 即应直接返回 |
| 一个进程一个 `Runtime` | `CefInitialize` / `CefShutdown` 进程级单例 | Runtime 不允许拷贝、不允许重复构造 |
| `Runtime` 析构后不能再建浏览器 | `CefShutdown` 之后不可再 `CefInitialize` | 文档 + 析构内先关浏览器再 Shutdown |
| 动态库加载后不可 `FreeLibrary` | CEF 内部有静态状态与线程 | 用导入库链接（编译期链接）即天然满足；不要 `LoadLibrary` 后卸载 |
| `CefRefPtr` / CEF 类型不跨 DLL 边界 | CEF 对象只能在其所在模块内释放 | `BrowserHandle` 用 pimpl 包裹，公共头零 CEF 类型 |
| renderer 进程不放 Qt / 业务 UI | 子进程只负责 V8 与 IPC | `jsapi_cef.dll` 不依赖 Qt |

### 4.6 扩展点

| 需求 | 做法 |
| --- | --- |
| 页面加载完成 / 崩溃 / 关闭回调 | `WebContainer::SetObserver`（`jsapi::cef::BrowserObserver`，CEF-free） |
| 换 UI 框架 | 新增一层 L3 变体（如 `jsapi_win32.dll`），L1/L2 不动 |
| 一个窗口多个 web 区 | 同一个 `Runtime` 下创建多个 `WebContainer` |
| 独立弹窗 | `new WebContainer(&runtime)` + `setCentralWidget` + `show()` |
| 业务自定义 CEF 行为（下载、右键菜单等） | 目前未开放。需要时在 L2 增加 CEF-free 的策略接口，**不要**让业务层直接 include CEF |

## 5. 前端调用

```js
// 根节点
Extention.version();        // "jsapi-lite/1.0"
Extention.nodes();          // ["demo", "host"]
Extention.objectStats();    // { handles, transient_live, release_refs }

// 命名节点（首次访问属性时触发一次同步 describe）
const demo = Extention.demo;

demo.add(2, 3);                    // 同步返回 5
const sum = await demo.sumAsync(20, 22);   // 异步
demo.count = 25;                   // 属性写（走 setter）
const n = demo.count;              // 属性读（走 getter）

// 对象句柄
const child = demo.child();
child.ping("hi");

// 事件
demo.addEventListener("hello", (name, ...args) => console.log(name, args));
demo.emit("hello", ["world", 42]);
```

注意事项：

- 节点属性是 `ObjectHandle`：`Extention.demo` 每次读取都会 describe 一次（句柄相同则复用同一代理对象）。
- 函数与属性声明在代理上，`Object.keys(demo)` 只能看到可枚举成员；只读属性不可枚举。
- 同步调用是**阻塞**的：在 UI 线程里执行耗时同步接口会卡住页面渲染与定时器。
- 异步接口返回原生 Promise，可用 `await` / `.then` / `.catch`。

## 6. 接入检查清单

- [ ] 节点类继承 `jsapi::JsObjectBase`，`DeclareMembers` 为 `const` 且无副作用
- [ ] 需要新对象时用 `LifeType::Transient`，并在返回时带上 `ctx.env()`
- [ ] 所有会在页面加载后访问的节点都在创建窗口前注册
- [ ] `CefClient::OnProcessMessageReceived` 转交给了 bridge，`OnBeforeClose` 调用了 `bridge->OnBeforeClose`
- [ ] 设置了 dispatcher 时确认它是阻塞式投递
- [ ] 插件函数里没有阻塞等待渲染进程的操作
- [ ] 插件 DLL 与依赖 DLL 在 exe 同目录（或已在 `PATH`）
- [ ] 同步接口耗时可预期（建议 <100ms），长任务走异步接口
- [ ] 插件函数幂等，不假设"页面崩溃前的调用一定完成"
- [ ] 异步函数体内没有调用 `DispatchEventSync`，事件回调链有明确深度上限

## 7. 可靠性边界与使用约束

框架在实现层做了兜底（异常捕获、崩溃隔离、容量与深度显式报错），但下列边界属于**设计上的取舍**，接入时必须遵守。

### 7.1 超时与长任务

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 同步 RPC 超时 | 固定 10s | 渲染进程侧 `SyncChannel::Send` |
| 同步事件超时 | 默认 10s | `DispatchEventSync(event, target, args, timeout_ms)` 可按调用覆盖 |

- **超时只结束等待，不取消后端执行**。插件函数会继续在该页的会话线程上跑完。
- 同一页面内请求**串行**执行：一个耗时 30s 的同步函数会阻塞该页后续所有请求（其他页面不受影响）。
- 建议：单个同步接口控制在 100ms 内；耗时逻辑改为异步接口，在后台线程完成后回调。
- 超时后迟到的回包/回执由 seq / invoke_id 校验丢弃，不会被后续调用误认。

### 7.2 嵌套深度与容量

| 项 | 取值 | 超限表现 |
| --- | --- | --- |
| 同步 RPC 嵌套深度 | 8 | `nested call depth exceeded` |
| 同步事件嵌套深度 | 8 | `nested event depth exceeded` |
| 请求 / 回包 | 1MB | `sync jsapi request exceeds shared-memory capacity` / `jsapi response exceeds shared-memory capacity` |
| 单条事件 | 1MB | 同步事件返回 `event channel overflow or event too large`；异步事件自动回退进程消息 |
| 事件槽数量 | 4 | 槽满时同步事件失败（不静默丢弃） |

同步事件与同步 RPC 嵌套会占用同一执行栈，不要在单个同步调用里构造无界的递归回调链。

### 7.3 异常

- **插件函数 / 属性抛出的 C++ 异常**会被框架捕获并转成 RPC 错误（`function 'x' threw: ...` / `property 'x' getter threw: ...`），不会终止宿主进程，且该节点后续调用仍然正常。异常只作兜底，不要当作正常控制流。
- **前端回调抛出的 JS 异常**在渲染进程内捕获，作为错误回执返回给插件，插件收到的是错误而不是等满超时。
- 回调返回失败（`ok=false`）后，同步事件路径会立即恢复可用，不需要重启页面。

### 7.4 页面崩溃（渲染进程终止）

- 通道按浏览器保留，重载后的新渲染进程直接复用，无需重新握手。
- 崩溃时：滞留的顶层/嵌套请求被丢弃；未派发的异步事件被清空；正在等待的同步事件立刻以 `render process terminated` 失败（不会白等 10s）；残留回包被作废；渲染侧 seq 用时间戳重新播种，避免与旧进程撞号。
- 结论：**插件函数应当幂等**，不要假设"页面崩溃前发起的那次调用一定已经完成"。
- 页面恢复后的首个同步请求到达时，该通道自动恢复同步事件能力。
- **界面导航/刷新**：请求携带的 `env` 以发起请求的当前 document 为准；新 document 建根对象时，框架会自动清理同一浏览器下旧 frame 注册的监听器，事件不会被派发到已销毁的 `callback_id`。渲染进程崩溃时，该浏览器的全部监听器一并清空。页面重新加载后需要重新 `addEventListener`，不要依赖上一个页面的监听器仍然有效。

### 7.5 线程与状态

- 异步 RPC 在**宿主 UI 线程**执行；其函数体内**禁止** `DispatchEventSync`（层级失配会返回 `level misaligned, sync nesting rejected`）。耗时逻辑请放到工作线程，完成后回到 UI 线程回调。
- 声明为 `ThreadAffinity::Worker`（默认）的成员**不得直接操作 Qt 控件**；需要操作控件请声明 `ThreadAffinity::UI`。误声明属于未定义行为，可能导致宿主崩溃（示例页保留了该演示按钮，仅用于观察）。
- 同一页面内函数串行、跨页面并行；跨页面共享的节点状态由插件自行加锁。

## 8. 设计取舍

分层与导出策略上的已知取舍，接入时不必规避，但需要知道边界在哪：

1. **`jsapi.dll` 导出全部符号**：省去给每个类加导出宏的成本，契约仍由公共头界定。若将来需要严格控制导出表，改为显式 `JSAPI_API` 即可，不影响分层。
2. **`include/jsapi_channel/` 是公开的**：它零 CEF/Qt，自测与非 Qt 宿主都可能需要；文档标注为「高级接口」，业务插件不鼓励直接用。
3. **`BrowserBridge` 仍在 `namespace jsapi_bridge`**：命名空间是历史命名，真正的边界是 DLL 与目录。改名会影响大量内部符号，收益低，暂不处理。
4. **`demo_plugin` 直接依赖 Qt Widgets**：它演示「插件操作宿主控件」，所以需要 Qt。真实业务插件若只做数据能力，可以不链 Qt。
