# 接入指南

本文说明如何把 JSAPI Lite 接入一个 CEF 宿主，并为前端提供可调用的 C++ 能力。

接入只有三件事：

1. **声明节点**：写一个 `JsObjectBase` 子类，在 `DeclareMembers()` 里填函数表。
2. **注册节点**：动态库插件导出工厂，或静态注册到宿主。
3. **宿主装配**：渲染进程挂 `JsApiRenderHandler`，浏览器进程挂 `JsApiBrowserBridge` 并转发进程消息。

---

## 1. 设计约定

| 概念 | 说明 |
| --- | --- |
| 根节点 | `window.Extention`，固定句柄 `0`，由 `JsRegistry` 在构造时创建 |
| 命名节点 | 通过 `RegisterNode("demo", factory)` 注册，在根节点上表现为属性 `Extention.demo` |
| 句柄 | 每个 C++ 对象在浏览器进程有一个自增 `handle`；跨进程只传句柄数字 |
| 代理 | 渲染进程为每个句柄建立一个 V8 对象，方法调用/属性访问都转成 RPC |
| 函数索引 | 声明顺序即 `index`；请求只带 `(handle, index)`，不传函数名 |
| 生命周期 | `Singleton`（进程内复用）或 `Transient`（随 JS 代理回收释放） |

渲染进程与浏览器进程的职责边界：

- 渲染进程**不持有业务对象**，只持有 V8 代理、回调函数和待回包 Promise。
- 浏览器进程**不接触 V8**，只处理 `JsValue` 与 JSON。

## 2. 声明节点

### 2.1 最小节点

```cpp
// my_node.h
#pragma once

#include "jsapi/js_object.h"

class MyNode final : public jsapi::JsObjectBase {
 protected:
  void DeclareMembers(jsapi::JsTableBuilder& table) const override {
    // 函数：名字、返回类型、参数表、实现
    table.Function(
        "add", jsapi::JsType::Int,
        {{"a", jsapi::JsType::Int}, {"b", jsapi::JsType::Int}},
        [](jsapi::JsObjectBase* /*self*/, jsapi::JsCallContext& ctx) {
          ctx.Return(jsapi::JsValue::Int(ctx.args()[0].AsInt() +
                                         ctx.args()[1].AsInt()));
        });

    // 只读属性
    table.Property("version", jsapi::JsType::String,
                   [](jsapi::JsObjectBase*) {
                     return jsapi::JsValue::String("my-1.0.0");
                   });

    // 可写属性：setter 返回 false 表示失败，error 会变成 JS 异常
    table.Property(
        "limit", jsapi::JsType::Int,
        [](jsapi::JsObjectBase* self) {
          return jsapi::JsValue::Int(static_cast<MyNode*>(self)->limit_);
        },
        [](jsapi::JsObjectBase* self, const jsapi::JsValue& value,
           std::string* error) {
          const std::int64_t next = value.AsInt();
          if (next < 0) {
            if (error) *error = "limit must be >= 0";
            return false;
          }
          static_cast<MyNode*>(self)->limit_ = next;
          return true;
        });
  }

 private:
  std::int64_t limit_ = 10;
};
```

### 2.2 声明函数

```cpp
JsTableBuilder& Function(const std::string& name,
                         JsType return_type,
                         std::vector<Param> params,
                         JsFunction function,
                         bool async = false);

JsTableBuilder& AsyncFunction(const std::string& name,
                              JsType return_type,
                              std::vector<Param> params,
                              JsFunction function);
```

- `Param` 支持聚合初始化：`{"name", JsType::Int}`，第三个字段 `optional` 默认为 `false`。
- 参数个数会被严格校验：必须落在 `[必填数, 声明总数]` 区间，否则报错。
- 声明类型用于**入参强转**（见 [API 参考](API参考.md#参数与返回值校验)）；返回值类型只写入 describe 信息，不做运行时转换，插件应返回匹配的 `JsType`。
- `AsyncFunction` 等价于 `Function(..., async = true)`。

参数表只在**首次访问**时构建并缓存，因此 `DeclareMembers` 应该是纯声明，不要在里面对可变状态做判断。若声明依赖会变化的状态，调用 `InvalidateTable()` 使其重建。

### 2.3 返回与报错

```cpp
void Return(JsValue value);   // 正常返回
void Fail(std::string error); // 失败：渲染进程会收到 JS 异常（同步）或 Promise reject（异步）
```

同步调用中 `Fail()` 会以 `throw` 形式抛出；异步调用中会 `Promise.reject(error)`。

### 2.4 返回对象句柄

一个节点可以返回另一个 C++ 对象，渲染进程会为它单独 describe 并建立新的 V8 代理：

```cpp
table.Function("child", jsapi::JsType::ObjectHandle, {},
               [](jsapi::JsObjectBase* /*self*/, jsapi::JsCallContext& ctx) {
                 auto child = std::make_shared<MyChildNode>();
                 ctx.Return(jsapi::JsValue::ObjectHandle(
                     ctx.registry()->AddObject(child, ctx.env())));
               });
```

`ctx.registry()` 是浏览器进程的句柄注册表，`ctx.env()` 是本次调用所在的 `(browser, frame)`。**推荐把 `env` 带上**，事件才能按来源定向回送。

### 2.5 生命周期

```cpp
class MyChildNode final : public jsapi::JsObjectBase {
 public:
  JSAPI_NODE_LIFE_TYPE(jsapi::LifeType::Transient);  // 随代理回收释放
};
```

| 类型 | 行为 | 适用 |
| --- | --- | --- |
| `Singleton`（默认） | 命名节点首次访问时创建，句柄缓存，所有页面共用同一个实例 | 全局服务、配置、会话 |
| `Transient` | 每次 `AddObject` / 访问都新建，渲染进程代理被 GC 时按引用计数释放 | 每次调用产生的新对象、临时上下文 |

生命周期由类内宏写死，注册时不可覆盖。`Singleton` 的对象在宿主进程存活期内不会被释放。

### 2.6 事件

所有节点自动拥有四个事件函数，**不需要在 `DeclareMembers` 里重复声明**：

| JS 方法 | 说明 |
| --- | --- |
| `addEventListener(event, fn)` | 登记回调，绑定当前 `(browser, frame)` |
| `removeEventListener(event, fn)` | 移除回调（同一 JS 函数对象复用同一回调句柄） |
| `dispatchEvent(event, args?, options?)` | 派发；`options` 支持 `{ browser, frame, excludeSelf }` |
| `getAllEventInfo()` | 返回 `[{ event, callback, browser, frame }]` |

C++ 侧主动通知：

```cpp
// 广播给所有监听者
int count = self->BroadcastEvent("progress", {JsValue::Int(50)});

// 只发给指定页面
jsapi::RpcEnv target;
target.browser_id = 1;      // <0 表示不限
target.frame_id = "2";      // 空表示不限
self->DispatchEvent("progress", target, {JsValue::Int(50)});
```

JS 回调签名固定为 `(eventName, ...args)`：

```js
demo.addEventListener("progress", (name, value) => {
  console.log(name, value);  // "progress" 50
});
```

> 事件从插件执行线程（默认 Qt GUI 线程）出发，经 `CefPostTask` 投递到 CEF UI 线程，再 `SendProcessMessage` 到渲染进程，因此是**异步**的，不保证与调用同一时刻到达。

## 3. 注册节点

### 3.1 方式一：动态库插件

插件是一个导出 `GetExtensionJsApiObj()` 的 DLL：

```cpp
// my_plugin.cpp
#include "my_node.h"
#include "jsapi/js_registry.h"

JSAPI_EXPORT_EXTENSION(MyNode);   // 展开成 extern "C" __declspec(dllexport) 工厂
```

CMake：

```cmake
add_library(my_plugin SHARED my_node.cpp my_plugin.cpp)
target_link_libraries(my_plugin PRIVATE jsapi_core Qt6::Widgets)  # 需要 Qt 时才链接
set_target_properties(my_plugin PROPERTIES PREFIX "" OUTPUT_NAME "my_plugin")
```

宿主加载：

```cpp
std::string error;
auto factory = jsapi::plugins::LoadDll("C:\\path\\my_plugin.dll", &error);
if (factory) {
  bridge->registry().RegisterNode("my", std::move(factory));
} else {
  // error 含 LoadLibrary / GetProcAddress 失败原因
}
```

- DLL 会被**常驻加载**（不 `FreeLibrary`），避免对象析构时模块已卸载。
- 插件依赖的 Qt DLL 必须能被找到；示例工程在 POST_BUILD 阶段把 Qt DLL 拷到 exe 同目录。
- 工厂返回裸指针，由 `std::shared_ptr` 接管（`LoadDll` 内已包装）。

### 3.2 方式二：静态注册

直接编进宿主的节点，不需要 DLL 边界：

```cpp
std::shared_ptr<jsapi::JsObjectBase> CreateHostNode() {
  return std::make_shared<HostNode>();
}

bridge->registry().RegisterNode("host", &CreateHostNode);
```

也可以注册现成实例（首次访问时才挂到句柄表）：

```cpp
bridge->registry().RegisterNode("host", std::make_shared<HostNode>());
```

### 3.3 注册时机

根节点的属性来自注册的节点名，函数表在**首次 describe 时构建**：

- 同名节点重复注册会保留已实例化对象的句柄，页面上已有的代理继续指向原对象。
- 页面加载**之后**新增的节点，当前页面不会自动多出属性，需要刷新页面。
- 因此应在创建浏览器窗口之前完成所有 `RegisterNode`。

## 4. 宿主装配

### 4.1 渲染进程

`CefApp::GetRenderProcessHandler()` 返回 `JsApiRenderHandler`。它在 `OnContextCreated` 里对 `handle 0` 做一次 describe，把 `window.Extention` 注入主 frame 的全局对象。

```cpp
class MyApp final : public CefApp {
 public:
  CefRefPtr<CefRenderProcessHandler> GetRenderProcessHandler() override {
    if (!render_handler_) render_handler_ = new jsapi_bridge::JsApiRenderHandler();
    return render_handler_;
  }
 private:
  CefRefPtr<jsapi_bridge::JsApiRenderHandler> render_handler_;
  IMPLEMENT_REFCOUNTING(MyApp);
};
```

> 浏览器进程与渲染进程复用同一个 exe 时，`CefExecuteProcess()` 会分流；渲染进程同样由这个 `CefApp` 提供 handler。

### 4.2 浏览器进程

```cpp
#include "jsapi_bridge/jsapi_browser_bridge.h"

CefInitialize(main_args, settings, app, nullptr);

auto bridge = std::make_shared<jsapi_bridge::JsApiBrowserBridge>();

// 可选：把插件函数的执行点切到宿主 UI 线程（阻塞式投递）
bridge->SetMainThreadDispatcher([](std::function<void()> task) {
  if (QThread::currentThread() == qApp->thread()) {
    task();
    return;
  }
  QMetaObject::invokeMethod(qApp, std::move(task), Qt::BlockingQueuedConnection);
});

bridge->registry().RegisterNode("demo", std::move(plugin_factory));
bridge->registry().RegisterNode("host", &CreateHostNode);
```

转发进程消息（`CefClient`）：

```cpp
bool MyClient::OnProcessMessageReceived(CefRefPtr<CefBrowser> browser,
                                       CefRefPtr<CefFrame> frame,
                                       CefProcessId source_process,
                                       CefRefPtr<CefProcessMessage> message) {
  return bridge_->OnProcessMessageReceived(browser, frame, source_process, message);
}

void MyClient::OnBeforeClose(CefRefPtr<CefBrowser> browser) {
  bridge_->OnBeforeClose(browser);   // 释放该页面缓存的同步回包通道
}
```

### 4.3 执行线程

| 场景 | 未设置 dispatcher | 设置 dispatcher 后 |
| --- | --- | --- |
| 同步 RPC | `SyncLoop` 工作线程 | 宿主 UI 线程 |
| 异步 RPC | CEF UI 线程 | 宿主 UI 线程 |
| 释放临时对象 | 同上（消息回调线程） | 宿主 UI 线程 |

约定：**dispatcher 必须在返回前执行完 task**（阻塞式）。示例使用 Qt 的 `Qt::BlockingQueuedConnection`，因为 bridge 在 dispatcher 返回后立刻写回包。

所有插件函数由 `process_mutex_` 串行执行，插件内部不需要为跨线程调用加锁；但**不要在插件函数里阻塞等待渲染进程**（例如模态 `QDialog::exec()`），否则会卡住整条 RPC 链。示例用非模态 `QMessageBox::open()`。

### 4.4 CMake 依赖

```cmake
target_link_libraries(my_host PRIVATE
  jsapi_bridge     # 依赖 jsapi_core + jsapi_rpc
  jsapi_host_nodes # 静态节点（如需要）
  libcef_lib libcef_dll_wrapper
  Qt6::Widgets
)
```

`jsapi_core` 与 `jsapi_rpc` 不依赖 CEF/Qt，可在没有 CEF 的环境里单独构建和单测。

## 5. 前端调用

```js
// 根节点
Extention.version();        // "jsapi-lite/1.0"
Extention.nodes();          // ["demo", "host"]
Extention.objectStats();    // { handles, transient_live, release_refs }

// 命名节点（首次访问属性时触发一次同步 describe）
const demo = Extention.demo;

demo.add(2, 3);                    // 同步返回 5
const sum = await demo.sumAsync(20, 22);   // 异步
demo.count = 25;                   // 属性写（走 setter）
const n = demo.count;              // 属性读（走 getter）

// 对象句柄
const child = demo.child();
child.ping("hi");

// 事件
demo.addEventListener("hello", (name, ...args) => console.log(name, args));
demo.emit("hello", ["world", 42]);
```

注意事项：

- 节点属性是 `ObjectHandle`：`Extention.demo` 每次读取都会 describe 一次（句柄相同则复用同一代理对象）。
- 函数与属性声明在代理上，`Object.keys(demo)` 只能看到可枚举成员；只读属性不可枚举。
- 同步调用是**阻塞**的：在 UI 线程里执行耗时同步接口会卡住页面渲染与定时器。
- 异步接口返回原生 Promise，可用 `await` / `.then` / `.catch`。

## 6. 接入检查清单

- [ ] 节点类继承 `jsapi::JsObjectBase`，`DeclareMembers` 为 `const` 且无副作用
- [ ] 需要新对象时用 `LifeType::Transient`，并在返回时带上 `ctx.env()`
- [ ] 所有会在页面加载后访问的节点都在创建窗口前注册
- [ ] `CefClient::OnProcessMessageReceived` 转交给了 bridge，`OnBeforeClose` 调用了 `bridge->OnBeforeClose`
- [ ] 设置了 dispatcher 时确认它是阻塞式投递
- [ ] 插件函数里没有阻塞等待渲染进程的操作
- [ ] 插件 DLL 与依赖 DLL 在 exe 同目录（或已在 `PATH`）
