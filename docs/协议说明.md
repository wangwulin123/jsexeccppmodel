# 协议说明

本文描述渲染进程与浏览器进程之间的三条通道：同步 RPC、异步 RPC、事件通知，以及对象释放消息。

> 这些是内部协议，只在 `src/bridge` 与 `jsapi_protocol.h` 中使用。业务接入方通常不需要直接处理，但排查问题时需要能读懂报文。

---

## 1. 总览

```
渲染进程                                   浏览器进程
   │                                          │
   │ ① 同步：写 Local\jsapi_req + SetEvent     │
   ├─────────────────────────────────────────▶│ SyncLoop 工作线程
   │                                          │  → 执行插件函数
   │ ② 同步回包：写 Local\jsapi_reply_<pid>    │
   │◀─────────────────────────────────────────┤  + SetEvent
   │                                          │
   │ ③ 异步：CefProcessMessage                │
   │    jsapi.async.request                   │
   ├─────────────────────────────────────────▶│ CEF UI 线程处理
   │    jsapi.async.response                  │
   │◀─────────────────────────────────────────┤
   │                                          │
   │ ④ 事件：jsapi.event                      │
   │◀─────────────────────────────────────────┤ CEF UI 线程
   │                                          │
   │ ⑤ 释放：jsapi.object.release             │
   ├─────────────────────────────────────────▶│
```

为什么同步不走进程消息：同步调用发生在渲染主线程的 V8 回调里，调用方立即阻塞；而 `CefFrame::SendProcessMessage` 需要等主线程回到消息循环才真正发出，会死锁。因此同步请求改用共享内存 + 命名事件直通。

## 2. 同步 RPC

### 2.1 共享内存名称

| 对象 | 名称 | 作用域 |
| --- | --- | --- |
| 请求映射 | `Local\jsapi_req` | 会话内全局，1 MB |
| 请求事件 | `Local\jsapi_req_evt` | 自动重置事件，渲染进程 `SetEvent` 唤醒浏览器线程 |
| 请求互斥量 | `Local\jsapi_req_mutex` | 多渲染进程串行写请求 |
| 回包映射 | `Local\jsapi_reply_<pid>` | 每个渲染进程独立，1 MB |
| 回包事件 | `Local\jsapi_reply_evt_<pid>` | 自动重置事件，浏览器进程 `SetEvent` 唤醒渲染进程 |

`<pid>` 是渲染进程 PID（`GetCurrentProcessId()`）。浏览器进程按回包通道名缓存句柄，避免每次 `OpenFileMapping + MapViewOfFile + OpenEvent`。

### 2.2 请求布局

```cpp
struct SharedRequestHeader {
  LONG seq;
  LONG length;
};
// 紧随其后是 length 字节的 UTF-8 JSON
constexpr int kRequestBufferBytes = 1 << 20;                  // 1 MB
constexpr int kRequestCapacity =
    kRequestBufferBytes - sizeof(SharedRequestHeader);        // ≈ 1 MB - 8
```

写入流程：

1. `WaitForSingleObject(request_mutex_, 5000)`
2. 写 `seq`、`length`、payload
3. `ReleaseMutex` → `SetEvent(request_event_)`

### 2.3 请求 JSON

```json
{
  "seq": 12,
  "op": "execute",
  "handle": 3,
  "index": 0,
  "async": false,
  "args": [1, 2],
  "env": { "browser": 1, "frame": "2" },
  "reply_map": "Local\\jsapi_reply_12345",
  "reply_event": "Local\\jsapi_reply_evt_12345"
}
```

| 字段 | 说明 |
| --- | --- |
| `seq` | 渲染进程自增序号，回包原样带回 |
| `op` | `describe` / `get` / `set` / `execute` |
| `handle` | 目标对象句柄，根节点为 `0` |
| `index` | 函数表索引；`describe` 时为 `-1` |
| `async` | 同步通道固定 `false` |
| `args` | 参数数组；`set` 时为单元素数组 |
| `env` | 调用方 `(browser, frame)`，浏览器侧会用真实对象回查覆盖，防伪造 |
| `reply_map` / `reply_event` | 仅同步通道需要，异步不需要 |

### 2.4 回包布局

```cpp
struct SharedReplyHeader {
  volatile LONG ready;   // 写完后置 1
  LONG seq;              // 必须与请求 seq 一致
  LONG length;
};
```

浏览器进程写入流程：

1. `ready = 0`
2. 写 `seq`、`length`、payload
3. `InterlockedExchange(&ready, 1)`
4. `SetEvent(channel->event)`

渲染进程：

1. `WaitForSingleObject(event_, 10000)`——**10 s 超时**
2. 校验 `ready == 1`、`seq` 一致
3. 读取 payload 并解析

超限处理：若回包 JSON 超过 `kReplyCapacity`，浏览器侧会改写为

```json
{ "seq": 12, "ok": false, "error": "jsapi response exceeds shared-memory capacity" }
```

### 2.5 回包 JSON

成功：

```json
{ "seq": 12, "ok": true, "value": 5 }
```

失败：

```json
{ "seq": 12, "ok": false, "error": "expected int, got string" }
```

`describe` 的 `value` 是对象描述（见 [API 参考](API参考.md#jsregistry)）。

### 2.6 值的编码

`JsValue` 序列化为 JSON：

| 类型 | 编码 |
| --- | --- |
| Null | `null` |
| Bool | `true` / `false` |
| Int | 整数 |
| Double | 浮点数 |
| String | 字符串 |
| Array | 数组 |
| Object | 对象 |
| ObjectHandle | `{"$obj": 3}` |
| CallbackHandle | `{"$cb": 7}` |

这两种句柄用独立键包裹，避免与普通对象字段混淆。

## 3. 异步 RPC

| 消息名 | 方向 | 参数 |
| --- | --- | --- |
| `jsapi.async.request` | renderer → browser | `args[0]` = 请求 JSON（与同步相同，无 `reply_map` / `reply_event`） |
| `jsapi.async.response` | browser → renderer | `args[0]` = 回包 JSON |

流程：

1. 渲染进程 `InvokeAsync`：分配 `seq`，把 `{promise, binding}` 存入 `pending_[seq]`，立即返回 Promise
2. `SendProcessMessage(PID_BROWSER, ...)`
3. 浏览器进程 `HandleAsyncRequest`：解析 → 用真实 `browser/frame` 覆盖 `env` → 投递执行点执行
4. 回包 `jsapi.async.response`，渲染进程按 `seq` 找 `pending_`，`ResolvePromise` / `RejectPromise`

注意：

- 异步通道**没有超时**。浏览器进程不回包（或 frame 已销毁），Promise 会永久 pending。
- `OnContextReleased` 会清理该上下文下的 `pending_`，避免泄漏。
- 消息在渲染进程主线程分发，Promise 回调也在主线程执行。

## 4. 事件消息

### 4.1 报文

消息名 `jsapi.event`，`args[0]` 为 JSON：

```json
{
  "name": "hello",
  "cb": 7,
  "args": ["world", 42]
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 事件名 |
| `cb` | 渲染进程登记的回调句柄 |
| `args` | 事件参数数组（可为空） |

### 4.2 流程

1. 插件线程调用 `BroadcastEvent` / `DispatchEvent`
2. `JsObjectBase::EmitTo` 在监听表中筛选目标（按 `browser` / `frame` / `exclude`）
3. 每个监听者调用 `JsEventSink::OnEvent`
4. `JsApiBrowserBridge::OnEvent` → `CefPostTask(TID_UI, EventDispatchTask)`
5. UI 线程按 `browser_id` + `frame_id` 回查 `CefBrowser` / `CefFrame`（失效则丢弃）
6. `SendProcessMessage(PID_RENDERER, jsapi.event)`
7. 渲染进程按 `cb` 找 `CefV8Value` 函数，构造参数 `(name, ...args)` 并执行

### 4.3 回调登记

`addEventListener(event, fn)` 是一次普通同步 RPC：

- 渲染进程把 `fn` 转成 `JsValue::CallbackHandle(id)`，同一个函数对象复用同一个 id（保证 `removeEventListener` 能匹配）
- 浏览器进程把 `{event, callback_id, env}` 存入节点的监听表
- 事件到达后只回传 `cb` 数字，不回传函数体

页面销毁时 `OnContextReleased` 清理该上下文登记的 `PendingPromise` 与回调表；已被浏览器侧记录的监听关系会随 frame 失效自动丢弃。

## 5. 对象释放消息

消息名 `jsapi.object.release`，`args[0]` 为对象句柄（int）。

触发：渲染进程的 V8 代理被 GC，`HandleReleaseGuard`（挂在 `CefV8Value::SetUserData`）析构时发出。

处理：

1. `JsApiBrowserBridge::OnProcessMessageReceived` 识别消息
2. 通过 `RunOnMainThread` 投递到插件执行点（对象析构可能销毁 Qt 控件，必须同线程）
3. `JsRegistry::ReleaseObject(handle)`：
   - 只处理 `Transient`，`handle <= 0` 或 `Singleton` 直接返回
   - 引用计数 `-1`，归零才真正 `objects_[handle].reset()`

## 6. 生命周期与错误处理

| 情况 | 行为 |
| --- | --- |
| 请求 JSON 解析失败 | 同步：回包 `ok=false, error="request must be an object"` 等；异步：写 stderr 并丢弃 |
| 句柄不存在 | `invalid object handle: N` |
| 索引不存在 | `invalid member index: N` |
| 参数个数不符 | `function 'x' expects A..B args, got N` |
| 参数类型不符 | `function 'x' arg 'a': expected int, got string` |
| 属性只读 | `property 'x' is read-only` |
| 插件 `ctx.Fail()` | 同步抛异常 / 异步 reject，错误文本原样透传 |
| 同步 10 s 超时 | 渲染侧抛 `sync jsapi call timed out` |
| 回包超过 1 MB | `jsapi response exceeds shared-memory capacity` |
| frame 失效 | 渲染侧 `jsapi frame is no longer valid`；事件直接丢弃 |

浏览器侧的协议错误只写 stderr，不回包（同步通道无法回包时渲染侧会等满 10 s 超时）。
