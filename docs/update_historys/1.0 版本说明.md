> 版本：v1.0
> 发布日期：2026-11-11
> 对应提交：`19660ef` feat: 初始化 JSAPI Lite 执行模型与示例工程
> 许可：MIT

## 一、版本概述

本版本是 JSAPI Lite 的**首个可用版本**，提供一套以**函数表**驱动的 CEF 精简 JSAPI 执行模型：前端通过 `window.Extention.<节点>.<方法>()` 直接调用浏览器进程中的 C++ 对象，无需手写 IPC 编解码，也不向 V8 暴露原生指针。

适用场景为「Web 前端 + C++ 宿主（Qt/MFC/自绘）」的混合应用，业务能力以节点（Node）为单位注册。

## 二、功能清单

| 能力 | 说明 |
| --- | --- |
| 函数表驱动 | 节点在 `DeclareMembers()` 中声明函数/属性，运行时按 `(handle, index)` 分发，前端拿不到明文函数名 |
| 同步调用 | 走共享内存 + 命名事件，单次往返约 30 µs |
| 异步调用 | 返回 Promise，走 `CefProcessMessage` |
| 属性即 RPC | `obj.count` / `obj.count = 5` 分别映射到 getter / setter，支持只读、类型校验与错误回传 |
| 事件系统 | 内置 `addEventListener` / `removeEventListener` / `dispatchEvent` / `getAllEventInfo`，支持按 `browser` / `frame` 定向派发与 `excludeSelf` |
| 对象句柄 | C++ 可返回新节点句柄，渲染进程自动建立新的 V8 代理；临时对象随代理 GC 释放（引用计数） |
| 两种扩展方式 | 动态库插件（导出 `GetExtensionJsApiObj()`）或静态注册（直接编入宿主） |
| 执行点可控 | `SetMainThreadDispatcher` 将所有插件函数切到宿主 UI 线程执行，插件中可直接操作窗口控件 |
| 可单测 | 核心层不依赖 CEF/Qt，`jsapi_self_test` 覆盖 113 条断言 |

## 三、工程结构

```
jsapi_demo/
├─ apps/qt_host/            Qt + CEF 宿主（浏览器进程、窗口、CefClient）
├─ include/
│  ├─ jsapi/                JsValue、函数表、节点基类、句柄注册表
│  ├─ jsapi_rpc/            请求解析与按索引分发（不依赖 CEF）
│  └─ jsapi_bridge/         渲染侧 JS 代理、浏览器侧桥、协议常量
├─ src/core|rpc|bridge/     上述三层的实现
├─ plugins/
│  ├─ demo_plugin/          动态库插件示例（DemoNode / DemoChildNode / BenchNode）
│  └─ host_nodes/           静态注册节点示例（HostNode）
├─ resources/               交互式示例页与性能基准页
├─ tests/self_test.cpp      113 条自测（不依赖 CEF/Qt）
└─ docs/                    接入指南 / API 参考 / 协议说明 / 构建与调试 / 性能基准
```

构建目标：`jsapi_core`、`jsapi_rpc`、`jsapi_bridge`、`demo_plugin`、`jsapi_host_nodes`、`jsapi_self_test`、`jsapi_qt_host`。

## 四、环境与依赖

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| CEF | 二进制包 | 默认识别 `<repo>/../../cef_binary`，可用 `-DCEF_ROOT=` 覆盖 |
| Qt | 6.8.3 msvc2022_64 | 默认识别 `<repo>/../../qt/6.8.3/msvc2022_64`，可用 `-DCMAKE_PREFIX_PATH=` 覆盖 |
| CMake | ≥ 3.21 | Visual Studio 生成器（x64） |

## 六、已知限制

1. **不支持同步嵌套**：同步 RPC 期间 C++ 再发起同步事件、前端在事件回调中再发起同步 RPC 的场景会在渲染线程/UI 线程/同步循环之间形成死锁。可用的退化形态是 `BroadcastEvent` 不等待、回调作为顶层调用执行。
2. **请求通道为单槽**：多页面并发同步调用存在槽位竞态，尚未做按页面隔离。
3. **平台限定 Windows**：共享内存、命名事件、`LoadLibrary` 均为 Win32 实现，移植需替换 `src/bridge` 下的同步通道。
4. **可靠性兜底有限**：插件异常未统一捕获，渲染进程崩溃/超时后的通道恢复与监听器清理尚无专门处理。

上述限制在后续版本（v1.1 起）中逐步解决，详见 `1.1 架构升级方案-同步RPC嵌套调用.md`。
